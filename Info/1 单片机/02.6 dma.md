# dma
## 概念
- 直接存储器存取（direct memory access，DMA）
- 在**外设和内存**之间或者**存储器和存储器**之间的高速数据传输
- **无须CPU干预**，数据可以通过DMA快速地移动
- 尤其适合**高频数据传输**场景

## 作用
- 没有 DMA 
	- 外设与内存的数据传输需要 CPU 全程参与
- 有DMA
	- 通过独立的控制器，直接接管数据传输过程
	- 仅在传输完成或出错时通过中断通知 CPU

## 特性
- 多通道设计
	- DMA1 有 7 个通道，DMA2 有 5 个通道
	- 每个通道可对应一个或多个外设的 DMA 请求
	- 通道间通过优先级仲裁（软件配置 + 硬件固定）决定传输顺序
- 传输方向
	- 外设→内存（如 ADC 采集数据存入 SRAM）；
	- 内存→外设（如 SRAM 数据通过 UART 发送）；
	- 内存→内存（如 SRAM 中数据块复制；ROM和RAM之间）。
- 传输模式
	- 正常模式：传输完成后，DMA 通道自动关闭，需手动重新使能
	- 循环模式：传输完成后自动重启，适合**周期性数据传输**（如 ADC 连续采样）
- 数据宽度
	- 支持 8 位、16 位、32 位（DMA_InitStruct.DMA_PeripheralDataSize和DMA_MemoryDataSize）
	- 需保证外设与内存的数据宽度匹配
- 地址增量
	- 可配置外设 / 内存地址是否自增（DMA_PeripheralInc/DMA_MemoryInc）
	- 如**传输数组时**需开启内存地址自增
	- 如 uart 接收数据时就不需要自增
- 传输触发源
	- 由外设产生 “DMA 请求信号” 触发传输
	- 不同外设对应固定的 DMA 通道（参考 “DMA 请求映射表”）

## 工作流程
- 可概括为“​**​请求-仲裁-传输-通知​**​”四步
- ​​请求阶段​​
	- 外设（如 UART 接收完成）向 DMA 控制器发送传输请求；
- 仲裁阶段​​
	- 若多个外设同时请求
	- DMA 仲裁器根据​​通道优先级​​（软件可配置）选择优先级最高的外设；
- 传输阶段​​
	- DMA 控制器接管系统总线
	- 直接从源地址（外设寄存器或内存）读取数据
	- 写入目标地址（内存或外设寄存器）
	- 无需 CPU 干预；
- 通知阶段​​
	- 传输完成后，DMA 控制器通过​​中断​​（传输完成、半传输、错误）通知 CPU
	- CPU 可随后处理数据或响应错误。

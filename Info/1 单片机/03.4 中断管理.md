# 中断管理
## 中断的本质
- **触发方式**
	- 由硬件异步触发
	- 与任务的 “主动执行” 不同。
- **优先级**
	- **中断优先级通常高于所有任务（硬件决定），可抢占正在运行的任务。**
- **执行要求**
	- 中断服务程序（ISR）必须**简短快速**（避免阻塞系统）
	- 禁止在 ISR 中调用`vTaskDelay()`、`xQueueReceive()`等阻塞类 API（中断不能被阻塞，否则会导致系统卡死）
	- 仅处理紧急事务（如数据缓存、状态标记）
	- 复杂逻辑应交给任务处理
	
## 中断管理原则
- **隔离保护**
	- **目的：保护内核数据结构（如就绪列表、队列）**
	- 在中断中访问时需通过专用 API（带`FromISR`后缀）
- **优先级划分**
- **延迟调度**
	- 中断中不直接进行任务切换，而是标记 “需要调度”
	- 在中断退出前或退出后由内核完成切换。
	
## 中断优先级
- 核心是 **通过 “优先级阈值” 控制中断对内核的访问权限**
- **硬件中断优先级**
	- Cortex-M 中断优先级由**8 位寄存器**控制（如 STM32 **用高4 位，共 16 级**）
	- 数值越小优先级越高（如 0 级最高，15 级最低）
- **FreeRTOS 的中断优先级**
	- 阈值把中断划分两类
		- 裸板中的优先级
		- RTOS中的优先级
			- configKERNEL_INTERRUPT_PRIORITY，RTOS中的表示最低中断优先级
			- configMAX_SYSCALL_INTERRUPT_PRIORITY，RTOS中的表示最高中断优先级
		- portDISABLE_INTERRUPTS
			- 会屏蔽RTOS中的优先级
	- 假如 `configMAX_SYSCALL_INTERRUPT_PRIORITY = 5`
		- 优先级 0~4 的中断
			- 仅能执行纯硬件操作
			- 不可调用 FreeRTOS API
			- 原因：优先级过高，若访问内核数据可能导致未保护的并发冲突
		- 优先级 5~15 的中断
			- 可调用`FromISR`类 API
			- 内核会通过临界区保护数据访问

## 临界区
- **BASEPRI 寄存器**
	- `#define portDISABLE_INTERRUPTS() vPortRaiseBASEPRI() // 屏蔽中断` 
	- `#define portENABLE_INTERRUPTS() vPortSetBASEPRI(0) // 开中断`
- 临界区保护​​
	- 调用`taskENTER_CRITICAL()`或`taskENTER_CRITICAL_FROM_ISR()`
	- 调用`taskEXIT_CRITICAL()`或`taskEXIT_CRITICAL_FROM_ISR()`
	- 进入临界区
		- 会自动操作 PRIMASK寄存器，屏蔽所有可屏蔽中断
		- 会**暂时禁止任务调度器工作**（通过关闭 PendSV 异常和 SysTick 中断，或修改调度器状态）
- **禁止在临界区内调用睡眠函数**
	- 睡眠函数依赖调度器
		- 睡眠函数作用
			- 挂起当前任务
			- 调度器切换到其他任务
		- 调度器关闭，导致不会切换任务，但是睡眠函数又因为中断停止而停止运行，就卡死了
	- 睡眠函数依赖中断
		- 系统无法处理定时器中断，这会导致 RTOS 的时间基准（如 tick count）停止更新

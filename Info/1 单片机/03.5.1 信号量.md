# ​信号量
## 优先级反转
- 现象
	- 低优先级任务占有某个共享资源
	- 高优先级任务因为需要等待该资源而被阻塞
	- 同时中优先级任务持续运行
	- **导致高优先级任务无法执行的现象**
- 解决方案
	- 优先级继承机制
		- 当高优先级任务（Task H）等待低优先级任务（Task L）释放资源时，Task L 的优先级会临时提升到与 Task H 相同的优先级。
		- 这样可以确保 Task L 快速完成并释放资源，避免中优先级任务（Task M）干扰。
	- 优先级天花板协议
		- **为每个共享资源分配一个固定的优先级（称为天花板优先级）**
		- 当任务获取资源时，其优先级会临时提升到天花板优先级，防止其他任务干扰。

## ​信号量区分
- 二值信号量
	- xSemaphoreCreateBinary
	- 可能导致优先级反转，**适合简单同步**
	- 不具有递归特性。
	- 适合用于简单的信号通知机制。
- 互斥信号量
	- xSemaphoreCreateMutex
	- **适合用于资源访问控制**
	- **具有递归特性**（即同一任务可以多次获取信号量，但需要相同次数的释放）。
	- **具有优先级继承机制**，避免优先级反转，适合资源保护
- 计数型信号量
	- xSemaphoreCreateCounting
	- 用于管理多个相同资源的访问，例如固定数量的缓冲区或硬件接口
	- 如果对计数信号量调用 xSemaphoreGive 的次数超过了信号量的最大计数值（uxMaxCount），信号量的计数值会保持在最大值

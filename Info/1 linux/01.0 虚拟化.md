# 虚拟化
## 虚拟化技术
### 虚拟机 和 容器
- **是目的不同的虚拟化技术**
- 虚拟机
    - 共享硬件
    - 不同的虚拟机可以运行不同类型的操作系统
- 容器
    - 共享操作系统
    - 不同的容器都可以运行在**全新**的操作系统

### Hypervisor
- 概念
	- Hypervisor（虚拟机监控程序）
    - 也叫做 VMM（Virtual Machine Monitor，虚拟机监视器） 
    - **它不是一款具体的软件，而是一类软件的统称**
    - **VMware、KVM、Xen、Virtual Box，都属于Hypervisor**
	- 目的：实现硬件资源的虚拟化与隔离
- 分类
	- **Type-1 虚拟化**
        - Baremetal Hypervisor，全虚拟化：Full-Virtualization
		- Hypervisor 直接部署在物理硬件上，性能接近原生
        - 虚拟机运行在hypervisor之上
        - 不需要对客户机操作系统或者应用程序进行修改（客户机操作系统或者应用程序像往常一样运行，意识不到虚拟环境的存在）
		- 代表技术：linux KVM、vmware ESXI、windows Hyper-V
	- **Type-2 虚拟化**
        - Hosted Hypervisor，半虚拟化：Para-Virtualization
		- Hypervisor 运行在宿主 OS上，性能略低
        - 物理机上安装正常的操作系统（例如Linux或Windows）
        - 然后在正常操作系统上安装hypervisor，生成和管理虚拟机
        - 半虚拟化需要对运行在虚拟机上的客户机操作系统进行修改（这些客户机操作系统会意识到它们运行在虚拟环境里）
		- 代表技术：Xen

### 容器
- 它是操作系统级别的虚拟化
- 也就是说只需要对操作系统进行抽象，**与Host主机共享内核和部分操作系统**，轻量
- 比如，LXC（Linux Container）和 Docker        

## 其他
### KVM
- Kernel-based Virtual Machine
- 是一种集成在Linux 内核中的开源虚拟化模块
- 工作方式
    - 提供核心虚拟化基础的内核模，并与用户空间程序（如QEMU）配合
    - 负责虚拟机的管理和模拟虚拟设备

### QEMU 
- 概念  
    - 支持 x86、ARM、RISC-V、MIPS 等多种架构
    - 提供丰富的虚拟设备支持，适合复杂的虚拟化场景
- 技术模式
    - 软件模拟(TCG - Tiny Code Generator)
        - QEMU最初的模式，它使用其内置的动态二进制翻译技术
        - **软件模拟所有 CPU 指令**
    - 结合硬件虚拟化(KVM/Xen)
        - KVM 在内核空间负责CPU 和内存的虚拟化
        - 而QEMU 则在用户空间负责处理IO 设备以及管理虚拟机

# IO
- 总结
    - 阻塞I/O，意味着一直等待设备可访问后再访问
    - 非阻塞I/O，使用poll()**查询设备是否可访问**
    - 异步通知，**设备通知用户自身可访问**，之后用户再进行I/O处理
    - **异步通知 + 数据直接传递到用户空间**
- 阻塞
    - 挂起，直至可以进行操作为止
    - 等待队列头部，wait_queue_head_t
- 非阻塞
    - 不挂起，它要么放弃，要么不停地查询，直至可以进行操作为止
    - **非阻塞I/O应用程序**通常会使用**select()和poll()系统调用**查询是否可对设备进行无阻塞的访问
    - select()和 poll()系统调用最终会使**设备驱动中的poll()函数**被执行
    - select()和poll()系统调用的本质一样，前者在BSD UNIX中引入，后者在System V中引入
    - 在Linux2.5.45内核中还引入了epoll()，即 扩展的poll()
- 异步通知    
    - fasync_struct，驱动中使用
    - signal，应用中使用信号
    - 流程
        - 用户空间设置文件的拥有者、FASYNC标志及捕获信号
        - 内核空间响应对文件的拥有者、FASYNC标志的设置并在资源可获得时释放信号
- 异步IO/AIO
    - **异步通知 + 数据直接传递到用户空间**
    - **完全异步：** I/O 操作由内核完成，进程无需轮询或等待。
    - **回调机制：** 操作完成后，内核通过回调函数通知进程。
    - **高效：数据直接传递到用户空间，减少了上下文切换**。
    - **缺点：** 编程复杂度高，支持的操作系统和文件系统有限。

# **总结：**
- **向量中断**和**非向量中断**是两种不同的中断处理机制，主要区别在于中断服务程序（ISR）的地址获取方式
- **向量中断**
    - 中断发生时，CPU 自动根据中断向量号跳转到对应的中断服务程序
    - 适合实时性要求高的场景，响应速度快，但灵活性较低。
- **非向量中断**
    - 中断发生时，跳转到一个固定的中断入口地址，由中断服务程序自行判断中断源并处理
    - 适合简单系统，灵活性高，但响应时间较长。

# **主要区别：**

| **特性**            | **向量中断**                  | **非向量中断**                |
|---------------------|------------------------------|------------------------------|
| **中断入口地址**    | 从中断向量表中获取            | 固定的中断入口地址            |
| **中断源判断**      | 不需要，直接跳转到对应地址    | 需要查询中断标志位或控制器    |
| **响应时间**        | 快                           | 慢                           |
| **实现复杂性**      | 较低                         | 较高                         |
| **灵活性**          | 较低                         | 较高                         |
| **适用场景**        | 实时性要求高的复杂系统        | 简单系统或中断源较少的场景    |

# **1. 向量中断**
## **定义：**
向量中断是一种中断机制，在中断发生时，CPU 会根据中断向量号（Interrupt Vector Number）从中断向量表中查找对应的中断服务程序地址。

## **特点：**
- **中断向量表：** 系统维护一个中断向量表，每个中断源对应一个固定的入口地址。
- **自动跳转：** 中断发生时，CPU 自动根据中断向量号跳转到对应的中断服务程序。
- **快速响应：** 由于中断向量表是预定义的，查找中断服务程序地址的过程非常高效。

## **优点：**
- 响应速度快，适合实时性要求高的系统。
- 中断服务程序地址固定，便于管理和调试。

## **缺点：**
- 中断向量表的大小有限，可能限制中断源的数量。
- 中断向量号需要预先分配，灵活性较低。

## **适用场景：**
- 嵌入式系统（如 MCU）中常用的中断机制。
- 实时操作系统（RTOS）中对中断响应时间要求较高的场景。

---

# **2. 非向量中断**
## **定义：**
非向量中断是一种中断机制，在中断发生时，CPU 不通过中断向量表，而是跳转到一个固定的中断入口地址，由中断服务程序自行判断中断源并处理。

## **特点：**
- **固定入口地址：** 所有中断共享一个固定的中断入口地址。
- **中断源判断：** 中断服务程序需要通过查询中断标志位或中断控制器来判断中断源。
- **灵活性高：** 中断服务程序可以动态处理不同的中断源。

## **优点：**
- 实现简单，不需要维护中断向量表。
- 灵活性高，适合中断源较少或中断优先级较低的场景。

## **缺点：**
- 响应时间较长，因为需要额外的时间判断中断源。
- 中断服务程序复杂度较高，容易出错。

## **适用场景：**
- 简单的嵌入式系统或资源受限的设备。
- 中断源较少且实时性要求不高的场景。

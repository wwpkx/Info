# Linux实现底半部的机制
- **软中断(Softirq)**：高效、不可阻塞，适合高频任务。
- **Tasklet**：基于软中断，轻量级、不可阻塞，适合简单任务。
- **工作队列(Workqueue)**：可阻塞，适合复杂或耗时任务。
- **线程化IRQ（Threaded IRQ）**：线程化，可睡眠或阻塞,适合复杂中断任务。

# **1. 软中断（Softirq）**
## **定义：**
软中断是Linux内核中一种高效的底半部机制，适合处理高频率触发的任务。

## **特点：**
- 运行在软中断上下文中，不能睡眠或阻塞。
- 优先级高于普通任务，但低于硬中断。
- 全局共享10个软中断向量。
- 可以在多个CPU上并行执行，但同一类型的软中断在同一CPU上是串行的。

## **使用场景：**
- 网络协议栈处理。
- 磁盘I/O操作。

## **示例：**
```c
void softirq_handler(struct softirq_action *action) {
    // 处理逻辑
}

open_softirq(MY_SOFTIRQ, softirq_handler); // 注册软中断
raise_softirq(MY_SOFTIRQ); // 触发软中断
```

# **2. Tasklet**
## **定义：**
Tasklet是**基于软中断实现**的一种底半部机制，适合处理轻量级、无需阻塞的任务。

## **特点：**
- 运行在软中断上下文中，不能睡眠或阻塞。
- 同一类型的Tasklet是串行执行的，不会并发运行。
- 不同类型的Tasklet可以并行运行。

## **使用场景：**
- 适合处理短时间的延迟任务，例如简单的网络数据包处理。

## **示例：**
```c
DECLARE_TASKLET(my_tasklet, tasklet_handler, data);

void tasklet_handler(unsigned long data) {
    // 处理逻辑
}

tasklet_schedule(&my_tasklet); // 调度Tasklet
```

# **3. 工作队列（Workqueue）**
## **定义：**
工作队列允许底半部任务在内核线程上下文中运行，因此可以执行可能阻塞的操作。

## **特点：**
- 运行在内核线程上下文中，可以睡眠或阻塞。
- 提供默认的全局工作队列，也可以创建自定义工作队列。
- 适合处理复杂或耗时的任务。

## **使用场景：**
- 需要访问用户空间数据或需要睡眠的任务。

## **示例：**
```c
struct work_struct my_work;

void work_handler(struct work_struct *work) {
    // 处理逻辑
}

INIT_WORK(&my_work, work_handler);
schedule_work(&my_work); // 调度工作队列
```

# **4. 线程化IRQ（Threaded IRQ）**
## **定义：**
线程化IRQ是将中断处理程序分为硬中断处理部分和线程化部分，线程化部分运行在内核线程上下文中。

## **特点：**
- 硬中断部分处理紧急任务，线程化部分处理复杂任务。
- 线程化部分可以睡眠或阻塞。
- 提高了中断处理的灵活性和实时性。

## **使用场景：**
- 适合需要长时间处理或可能阻塞的中断任务。

## **示例：**
```c
irqreturn_t irq_handler(int irq, void *dev_id) {
    return IRQ_WAKE_THREAD; // 唤醒线程化部分
}

irqreturn_t thread_handler(int irq, void *dev_id) {
    // 线程化处理逻辑
    return IRQ_HANDLED;
}

request_threaded_irq(irq, irq_handler, thread_handler, flags, "my_irq", dev_id);
```

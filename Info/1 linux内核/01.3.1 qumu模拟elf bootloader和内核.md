当然可以同时包含！实际上，**真实的嵌入式系统启动流程就是 bootloader（如 U-Boot）先运行，再由 bootloader 加载并启动内核**，QEMU 完全支持模拟这一完整流程。之前的示例分开说明，只是为了简化不同阶段的讲解，并非两者不能共存。


### 为什么需要同时包含？
在真实硬件中，启动流程是固定的：  
`硬件初始化 → Bootloader（如 U-Boot）运行 → Bootloader 加载内核 → 内核启动 → 挂载根文件系统`  

- **Bootloader（如 U-Boot）** 的作用：初始化硬件（内存、外设）、提供交互界面（方便手动操作）、从存储设备（如 SD 卡）读取内核和设备树到内存、最终启动内核。  
- **内核** 的作用：接管系统后，初始化驱动、管理资源、启动用户态程序。  

因此，QEMU 模拟时，同时包含两者才能复现真实的启动流程，尤其适合调试 Bootloader 如何加载内核的过程。


### 如何在 QEMU 中同时模拟 Bootloader 和内核？
以下是完整流程：先启动 U-Boot，再通过 U-Boot 加载并启动内核，步骤如下：


#### 1. 准备文件
需要 4 个关键文件（前三个需提前编译）：  
- `u-boot.imx`：i.MX6ULL 的 U-Boot 镜像（Bootloader）。  
- `zImage`：Linux 内核镜像。  
- `imx6ull-14x14-evk.dtb`：设备树文件。  
- `rootfs.ext4`：根文件系统（ext4 格式）。  


#### 2. 将内核和设备树放入“虚拟存储”
U-Boot 需要从存储设备（如 SD 卡）读取内核和设备树，因此需将 `zImage` 和 `.dtb` 放入根文件系统的某个目录（如 `/boot`）：  
```bash
# 临时挂载根文件系统（需 root 权限）
mkdir -p mnt_root
sudo mount rootfs.ext4 mnt_root

# 创建 /boot 目录并复制内核和设备树
sudo mkdir -p mnt_root/boot
sudo cp zImage mnt_root/boot/
sudo cp imx6ull-14x14-evk.dtb mnt_root/boot/

# 卸载
sudo umount mnt_root
```


#### 3. 启动 QEMU 并运行完整流程
```bash
qemu-system-arm \
  -M imx6ull \                  # 模拟 i.MX6ULL 硬件
  -cpu cortex-a7 \              # 匹配 CPU 架构
  -m 512M \                     # 内存大小
  -kernel u-boot.imx \          # 先加载 U-Boot（Bootloader）
  -sd rootfs.ext4 \             # 虚拟 SD 卡（包含根文件系统和 /boot 下的内核）
  -serial stdio \               # 串口重定向到终端
  -net nic -net user \          # 虚拟网络
  -nographic \                  # 无图形界面，仅终端
  -append "root=/dev/mmcblk0 rw rootwait"  # 内核启动参数（U-Boot 会传递给内核）
```


#### 4. 在 U-Boot 中手动加载并启动内核
启动后，QEMU 会先进入 U-Boot 命令行（类似真实硬件的启动过程），此时需要手动执行加载内核的命令：  
```bash
# U-Boot 命令行中执行：

# 1. 识别 SD 卡（QEMU 中通常为 mmc 0）
mmc dev 0

# 2. 挂载 SD 卡的根文件系统分区（假设为第 1 分区）
fatload mmc 0:1 0x80800000 /boot/zImage       # 读取内核到内存地址 0x80800000
fatload mmc 0:1 0x83000000 /boot/imx6ull-14x14-evk.dtb  # 读取设备树到内存地址 0x83000000

# 3. 启动内核（传递启动参数）
bootz 0x80800000 - 0x83000000
```

执行后，U-Boot 会将内核和设备树交给 CPU，内核开始启动，最终进入根文件系统的命令行。


### 为什么之前的示例分开展示？
- 若只想快速测试内核功能，可跳过 U-Boot，直接用 QEMU 的 `-kernel` 参数加载内核（简化流程，适合内核调试）。  
- 若要调试 Bootloader 或复现真实启动流程，则必须包含 U-Boot，由它负责加载内核。  


### 总结
Bootloader 和内核是**启动流程的两个阶段**，QEMU 完全支持同时模拟。同时包含两者能更真实地复现硬件启动过程，适合调试 Bootloader 与内核的交互；跳过 Bootloader 则适合快速验证内核功能。根据开发需求选择即可。

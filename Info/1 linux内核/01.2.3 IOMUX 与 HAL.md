| 维度   | IOMUX（输入输出复用器）                                        | HAL（硬件抽象层）                                                                            |
| ---- | ----------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 定位   | 属于**硬件层面**的功能复用机制，是芯片内部的物理设计（由寄存器、多路选择器等硬件组成）。        | 属于**软件层面**的抽象层，是一组 API 接口，用于屏蔽不同硬件的差异。                                                |
| 作用   | **解决 “引脚数量有限 vs 功能需求多” 的硬件矛盾**，实现引脚功能的动态切换。           | **解决 “软件适配不同硬件” 的效率问题**，让上层应用无需关心底层硬件细节。                                              |
| 实现方式 | 通过芯片内部的**复用选择寄存器和电气属性寄存器**（如上拉 / 驱动强度配置）实现。           | 通过函数封装（如 HAL_GPIO_Init()、HAL_UART_Transmit()）实现，**将硬件操作抽象为统一接口**                      |
| 典型场景 | 配置某引脚为 “UART 接收” 还是 “GPIO 输入”<br>设置引脚的上拉电阻和驱动强度       | 调用 HAL_UART_Transmit() 发送数据，无需关心 UART 引脚的具体复用配置和寄存器地址。                                |
| 依赖关系 | **是 HAL 实现的硬件基础**——HAL 配置外设功能时，底层需通过 IOMUX 选择引脚的复用模式。 | **是 IOMUX 配置的软件封装**—— 用户通过 HAL 接口间接完成 IOMUX 配置（如 STM32 的 GPIO_InitTypeDef 中包含复用功能选择）。 |

# 内核启动流程
- 固件阶段（Firmware：BIOS/UEFI）
	- **作用**
		- 硬件上电后第一个运行的程序
		- 负责初始化基础硬件并加载引导程序（Bootloader）
	- **主要任务**
		- **硬件自检（POST）**
		- **初始化硬件**, 关闭看门狗、配置时钟、初始化内存、初始化串口、检测存储设备
		- **加载引导程序**
- 引导程序阶段（Bootloader）
	- 作用
		- 位于固件和内核之间，负责加载内核镜像到内存并传递启动参数
		- **最终跳转到内核入口**
	- 常见实现
		- x86 架构常用 GRUB2
		- ARM 架构常用 U-Boot
		- 嵌入式系统常用 Barebox 
	- 主要任务
		- 加载内核镜像
		- 加载初始化 ramdisk
			- 读取initrd（初始化内存磁盘）或initramfs（内存文件系统）到内存
			- 用于**临时挂载根文件系统**
		- 传递启动参数
			- 通过bootargs向内核传递配置
			- 如根文件系统路径、控制台设备、调试参数等
			- 如root=/dev/sda1 console=ttyS0
		- 跳转到内核入口
			- Bootloader 释放硬件控制权
			- 跳转到内核的汇编入口地址（如 x86 的startup_32/64，ARM 的stext）
- 汇编入口（arch/xxx/boot/compressed/head.S）
	- 解压缩内核：先解压原始内核（vmlinux）到内存。
	- 硬件初始化
		- 设置 CPU 模式（如 ARM 的 SVC 模式）
		- 关闭中断、禁用 MMU（内存管理单元）
		- 初始化临时页表（为 C 代码运行启用内存映射）。
	- 跳转到 C 入口
		- 跳转到内核的 C 语言入口函数（如start_kernel）。
- 核心初始化（start_kernel 函数，init/main.c）
	- 核心数据结构初始化
	- 硬件相关初始化
	- 启动 init 进程前的准备：
		- 挂载initrd/initramfs（临时根文件系统），加载根设备所需的驱动（如 SATA、NVMe 驱动）。
		- 调用rest_init函数，创建第一个内核线程（kernel_init）
		- 执行initrd中的脚本（如/init），检测并挂载真实根文件系统（通过root=参数指定，如/dev/sda2）。
		- 根文件系统切换完成后，卸载initrd，释放临时内存。
- 用户空间初始化（User Space）
	- 通过kernel_init进程启动用户态的第一个进程（PID=1）
	- 启动 init 进程
	- 系统服务初始化
	- 进入用户态

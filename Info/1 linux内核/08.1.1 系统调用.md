# 系统调用

## 概念
- **用户态与内核态的安全桥梁**
- **是用户态应用程序请求内核提供服务的统一接口**
- 内核
	- 是操作系统的核心
	- 管理着所有硬件资源（CPU、内存、磁盘、网络）和系统级资源（进程、文件、信号）
	- 内核的所有能力都通过系统调用暴露给用户程序
- **系统调用 vs 库函数**
	- 系统调用是内核提供的 “原始接口”，无封装、更底层
	- 库函数是对系统调用的封装
- **系统调用 vs 中断 vs 陷阱（Trap）** 
	- 系统调用是 “软件主动触发”，核心目的是 “满足用户程序的服务请求”
	- 中断是 “硬件被动触发”，核心目的是 “处理硬件事件”
	- 系统调用本质是一种 “软件陷阱”（主动触发的异常），通过特殊指令（如 int 0x80、syscall）触发内核态切换

## 系统调用过程总结
- 用户态触发 → 上下文切换 → 内核处理 → 上下文恢复 → 返回用户态
- **系统调用号**
	- 每个系统调用有唯一编号
	- `write()` 的编号是 1，`open()` 是 2，`fork()` 是 57
- **传参方式**
	- 系统调用通过寄存器传参
	- 64 位用 `rax` 存系统调用号，`rdi`/`rsi`/`rdx`/`r10`/`r8`/`r9` 存参数；超过 6 个时需通过内核栈间接传递

## 系统调用过程
- 用户态触发系统调用
	- `printf("hello")` 最终会调用 `write(int fd, const void *buf, size_t count)`
	- 把系统调用号（`write()` 是 1）存入 `rax`；
	- 把参数 `fd=1`（标准输出）存入 `rdi`，`buf="hello"` 存入 `rsi`，`count=5` 存入 `rdx`；
	- 执行 `syscall` 指令，主动请求切换到内核态。
- 用户态 → 内核态切换（上下文保存）
	- **硬件自动操作**
		- 切换 CPU 特权级到内核态（Ring 0）
		- 将 CPU 的 `SS`/`ESP` 切换为内核栈（与中断切换逻辑一致）
		- 将用户态`SS RSP RFLAGS CS RIP` 压入 **当前进程的内核栈**
	- **内核软件压栈**
		- entry_SYSCALL_64
		-  保存用户态的通用寄存器和段寄存器

# input 子系统

## 概念
- 是管理输入设备的核心框架，提供了统一的事件处理机制
- 通过它，开发者可以轻松实现输入设备的驱动程序，并在用户空间处理输入事件

## 核心组件
1. **输入设备驱动（Input Device Driver）**
   - 负责与硬件交互，采集输入事件（如按键、触摸等）
   - 将事件传递给 Input 子系统
2. **输入事件处理（Input Event Handling）**
   - 通过标准化的事件接口（`input_event` 结构）处理输入事件
   - 支持多种事件类型，如按键事件、鼠标移动事件等
3. **输入设备接口（Input Device Interface）**
   - 提供用户空间访问输入设备的接口
   - 常见接口包括 `/dev/input/eventX`、`/dev/input/mouseX` 等

## 工作流程
1. **事件采集**
   - 输入设备驱动从硬件中采集输入事件（如按键按下）
2. **事件传递**
   - 驱动将事件传递给 Input 子系统
3. **事件分发**
   - Input 子系统将事件分发到用户空间的设备文件
4. **用户空间处理**
   - 用户空间程序通过设备文件读取事件并进行处理

## 关键数据结构
- input_dev
- input_event

## 事件类型
- **`EV_KEY`**：按键事件（如键盘按键、鼠标按键）
- **`EV_REL`**：相对位移事件（如鼠标移动）
- **`EV_ABS`**：绝对位移事件（如触摸屏坐标）
- **`EV_MSC`**：杂项事件（如 LED 状态）
- **`EV_SW`**：开关事件（如电源开关）

## 优点
1. **统一接口**：支持多种输入设备，提供标准化的事件接口
2. **灵活性**：支持用户自定义输入设备和事件
3. **扩展性**：易于添加新设备和功能
